Copilot Studio agent: private MCP server, Zscaler ZIA egress, Zscaler AI Guard

One controlled path to the Internet — every prompt, tool call and answer checked by AI Guard.

The flow, step by step

  1. Sign-in. The agent requires Microsoft authentication, so Copilot Studio knows the user (System.User.PrincipalName). Anonymous channels are refused.
  2. Prompt check. Topic AI Guard - prompt runs on every message before generative orchestration and calls AI Guard resolve-and-execute-policy directly through a custom connector: direction IN, user = UPN, transactionId = a new UUID. BLOCK → "Your message was blocked by Zscaler AI Guard (transaction …)" and the turn ends.
  3. Orchestration. Generative orchestration picks the MCP tool. Built-in web search, model knowledge and public-website knowledge are off — and blocked by the environment's data policy — so Internet questions can only be answered through the tool.
  4. Private reach. The tool is a custom connector to the MCP server's internal FQDN. Through the environment's NetworkInjection enterprise policy (Managed Environment), the call leaves from the delegated subnet; a private DNS zone resolves the name to the internal load balancer. The MCP server has no public IP and no public DNS record, and requires an API key.
  5. Tool input check. The MCP server sends the model-chosen query to AI Guard (execute-policy). Blocked or no verdict → no search.
  6. Egress through ZIA. The search goes to Tavily through the ZIA explicit proxy from the NAT gateway's static IP (a ZIA Location). The NSG denies every other Internet destination.
  7. Tool output check. Every result is checked as model input (indirect prompt injection); flagged results are dropped before they reach the model.
  8. Response check. Topic AI Guard - response holds the generated answer (System.ContinueResponse = false), checks it with direction OUT for the same user, and sends it only if it is not blocked.
